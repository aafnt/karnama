# کارنما

> کارها را ببین، انجام بده، پیگیری کن.

اپلیکیشن اندروید شخصی برای مدیریت کارهای روزمره‌ی اداری — ساده، سریع، کاملاً فارسی و RTL، با تقویم شمسی.

## ساختار فنی

- Kotlin + Jetpack Compose + Material 3
- معماری MVVM + Repository Pattern
- Room (پایگاه‌داده محلی) + Kotlin Coroutines/Flow
- DataStore برای تنظیمات (تم روشن/تاریک/سیستم)
- Navigation Compose

## اجرای پروژه

1. پروژه را در Android Studio (نسخه‌ی Koala یا جدیدتر) باز کنید؛ Studio به‌طور خودکار Gradle Wrapper را می‌سازد.
2. یا از خط فرمان، در صورت نصب بودن Gradle 8.7 روی سیستم: `gradle assembleDebug`

### فونت Vazirmatn (مرحله‌ی اختیاری ولی توصیه‌شده)

به‌دلیل محدودیت دسترسی به اینترنت در محیطی که این پروژه ساخته شد، فایل‌های باینری فونت اضافه نشده‌اند. برنامه با فونت پیش‌فرض سیستم کامپایل و اجرا می‌شود، اما برای رسیدن به ظاهر دقیق طراحی‌شده:

1. سه فایل زیر را از <https://github.com/rastikerdar/vazirmatn> دانلود کنید:
   `Vazirmatn-Regular.ttf`, `Vazirmatn-Medium.ttf`, `Vazirmatn-SemiBold.ttf`
2. آن‌ها را به‌ترتیب با نام‌های `vazirmatn_regular.ttf`، `vazirmatn_medium.ttf` و `vazirmatn_semibold.ttf` در پوشه‌ی `app/src/main/res/font/` کپی کنید.
3. فایل `app/src/main/java/com/karnama/app/ui/theme/Type.kt` را باز کنید و طبق راهنمای بالای فایل، بلوک کامنت‌شده را فعال کنید.

## آپلود در GitHub و کامپایل خودکار

یک Workflow آماده در `.github/workflows/android-build.yml` قرار دارد. بعد از Push کردن این پروژه به یک ریپوی GitHub:

- روی هر Push به شاخه‌ی `main` و هر Pull Request، برنامه به‌صورت خودکار کامپایل می‌شود.
- خروجی APK امضاشده به‌عنوان Artifact در تب Actions قابل دانلود است.
- روی Push به `main`، یک GitHub Release جدید هم با APK ضمیمه ساخته می‌شود.

هیچ تنظیم اضافه‌ای (مثل GitHub Secrets) لازم نیست؛ کلید امضا از قبل در پروژه قرار دارد (به بخش بعد نگاه کنید).

## ⚠️ نکته‌ی خیلی مهم: به‌روزرسانی بدون نیاز به Uninstall

اندروید هر APK جدید را فقط زمانی به‌عنوان «آپدیت» یک برنامه‌ی نصب‌شده قبول می‌کند که:

1. **applicationId** یکسان بماند: `com.karnama.app` (این را تغییر ندهید).
2. **امضای (Signing Key) APK** با نسخه‌ی قبلی یکسان باشد.
3. **versionCode** نسبت به نسخه‌ی نصب‌شده بزرگ‌تر باشد.

برای شرط دوم، یک Keystore دائمی در مسیر `keystore/karnama-release.jks` در همین پروژه ساخته شده و در `app/build.gradle.kts` به‌طور پیش‌فرض استفاده می‌شود. **این فایل را هرگز حذف، جایگزین یا از Git خارج نکنید** — اگر این فایل عوض شود یا مقادیر رمز آن تغییر کند، امضای Build بعدی فرق می‌کند و کاربران برای نصب آپدیت مجبور می‌شوند برنامه‌ی قبلی را Uninstall کنند (و همه‌ی داده‌هایشان را از دست بدهند).

روال درست برای هر آپدیت:

1. تغییرات کد را اعمال کنید.
2. در `app/build.gradle.kts` مقدار `versionCode` را یک واحد افزایش دهید (و در صورت تمایل `versionName` را هم به‌روزرسانی کنید).
3. اگر ساختار جدول‌های دیتابیس (Entityها) تغییر کرده، حتماً یک Migration مطابق راهنمای `app/src/main/java/com/karnama/app/data/local/Migrations.kt` اضافه کنید و نسخه‌ی `KarnamaDatabase` را بالا ببرید. **هرگز** از `fallbackToDestructiveMigration()` استفاده نکنید، چون داده‌های کاربر را پاک می‌کند.
4. Push کنید؛ GitHub Actions به‌طور خودکار APK جدید را با همان کلید امضا می‌کند.
5. کاربر APK جدید را روی نسخه‌ی نصب‌شده نصب می‌کند — بدون Uninstall و بدون از دست رفتن داده‌ها.

> امنیت: رمز عبور Keystore به‌صورت پیش‌فرض در `build.gradle.kts` نوشته شده تا Build در GitHub Actions بدون تنظیم اضافه کار کند. اگر ریپو را Public کردید و نگران امنیت هستید، می‌توانید مقادیر را از طریق متغیرهای محیطی `KARNAMA_KEYSTORE_PATH`، `KARNAMA_KEYSTORE_PASSWORD`، `KARNAMA_KEY_ALIAS` و `KARNAMA_KEY_PASSWORD` (مثلاً به‌عنوان GitHub Secrets) بازنویسی کنید — همچنان با همان Keystore فعلی، فقط پسورد را جای دیگری نگه دارید.

## پشتیبان‌گیری داده‌ها

مستقل از موضوع بالا، از مسیر «بیشتر ← پشتیبان‌گیری / بازیابی» می‌توانید در هر زمان یک فایل JSON از تمام کارها، اقدامات و متن‌های آماده تهیه یا بازیابی کنید — یک لایه‌ی محافظتی اضافه، جدا از مکانیزم آپدیت بدون Uninstall.

## وضعیت فعلی پیاده‌سازی

پیاده‌سازی‌شده: صفحه‌ی اصلی (امروز/دیروز/فردا)، افزودن سریع کار، Checkbox با انیمیشن، اقدامات هر کار (Bottom Sheet + Timeline)، متن‌های آماده و جستجوی هوشمند، انتقال کار (تکی/چندتایی) به فردا یا تاریخ دلخواه، تقویم شمسی مستقل، حالت روشن/تاریک/سیستم، پشتیبان‌گیری و بازیابی.

نکاتی که قبل از انتشار عمومی بهتر است دوباره بررسی شوند:
- نام دقیق برخی آیکون‌های Material (`CalendarMonth` و چند AutoMirrored) در نسخه‌ی کتابخانه‌ی استفاده‌شده — اگر Android Studio هنگام Sync خطای «Unresolved reference» داد، جایگزین نزدیک آن آیکون را از پیشنهادهای IDE انتخاب کنید.
- فونت Vazirmatn (بخش بالا).
- تست دستی رفتار Migration هنگام اولین تغییر واقعی در ساختار دیتابیس.
